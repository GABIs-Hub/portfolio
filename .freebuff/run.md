This thread's workspace is the same directory as the main checkout:
`D:\GABI\Wrks\VsCode Wrks\portfolio-site`.

Stack: Next.js 16 (App Router, Turbopack), React 19, TypeScript, Tailwind CSS v4.
Package manager: npm (the only lockfile is `package-lock.json`).

## 1. Reproduce the uncommitted artifacts

A fresh checkout needs only dependencies. There are **no env files** in this project
(no `.env`, `.env.local`, or `.env.*` exist, and no secret is required to build or run —
content is static in `src/lib/site.ts`).

```bash
npm install          # or: npm ci   (uses package-lock.json)
```

Nothing else to copy or generate. `next-env.d.ts` is generated by Next.js and is
rewritten on each build/dev start; do not hand-edit it.

Uncommitted work in this worktree (the light-mode theme system) is plain source, so it
is already present after checkout: `src/app/globals.css`, `src/app/layout.tsx`,
`src/components/site-header.tsx`, `src/app/work/[slug]/page.tsx`, plus the new
`src/lib/theme.ts` and `src/components/theme-toggle.tsx`.

## 2. Run the server

Port `3000` was **not** free in this environment: an older detached `next dev` instance
already holds it, and that instance also owns the single-instance dev lock at
`.next/dev/lock`. A second `next dev` in this directory therefore fails with
"Unable to acquire lock". So this preview runs the **production server** on a free port
instead, which needs no dev lock and serves exactly what ships.

```bash
npm run build                 # ~60-90s; required before `next start`
npm run start -- -p 3001
```

Start it detached (Windows / PowerShell), logging to the file below:

```bash
powershell -NoProfile -Command "(Start-Process -FilePath 'npm.cmd' -ArgumentList 'run','start','--','-p','3001' -WorkingDirectory 'D:\GABI\Wrks\VsCode Wrks\portfolio-site' -RedirectStandardOutput 'D:\GABI\Wrks\VsCode Wrks\portfolio-site\.freebuff\preview-67f38eb9-ce76-474b-be77-649584e03eee.log' -RedirectStandardError 'D:\GABI\Wrks\VsCode Wrks\portfolio-site\.freebuff\preview-67f38eb9-ce76-474b-be77-649584e03eee.log.err' -WindowStyle Hidden -PassThru).Id"
```

Notes that cost time to rediscover:

- `Start-Process` needs the real executable name (`npm.cmd`, `node.exe`); it does not
  resolve Git Bash shims. stdout and stderr must go to **different** files.
- The command may not print a pid back to the invoking shell before the tool call times
  out. The launch still succeeds — confirm with
  `netstat -ano | grep :3001` and register the **listening** pid, not a wrapper pid.
- Cold start took ~23s. Wait until the URL answers before registering.
- If a stale `next dev` instance is running, it can serve a cached CSS chunk and make
  source edits look like they did not apply. The production server has no such cache;
  re-run `npm run build` after editing source to refresh the preview.

Preview URL: `http://localhost:3001/`
